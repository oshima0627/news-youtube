# 既知の問題と未検証項目

実装完了時点（2026-08-11）で分かっている、**稼働前に片付けるべきこと**。
レビューで見つかったが今回の修正範囲外にしたものも含む。

## 1. 実データで採用0件になる（最優先）

`--dry-run` を実機で回したところ、**当日のRSS候補20件すべてが「根拠なし」で見送り**
になった。パイプラインは端から端まで通り、テストも通るが、**実データを入れると1本も
作れない。**

原因は検索語の作り方。`sources._keyword()` は見出しから記号を除いて先頭40文字を
そのまま検索語にしているが、国会会議録の全文検索（`any` は空白区切りのAND）では
40文字の長い文字列がヒットしない。

**直すときの必須条件:** 検索語を短くすると、今度は**無関係な引用が拾える**ように
なる。実測で `高市 総理 答弁` の最上位ヒットは題材と無関係な別議員の発言だった。
`is_admissible` はホストと引用の長さしか見ておらず、**引用が題材と関係あるかを
誰も検証していない**。

検索語の修正には、**関連性の検証を必ず同梱すること**（見出しの主要語が引用に
含まれるか、など）。0本のままより、無関係な引用で作った動画のほうが遥かに危険。

## 2. 手動CLI経路が引用の検証を通らない

`write_script.py` → `build_short.py` を手で叩く経路は、`run_daily` にある
`ensure_grounded_card()`（`quote_excerpt` が一次資料の部分文字列かの検証）を
**通らない**。モデルが作った文字列が、一次資料の出典キャプション付きで
引用カードに描画されうる。

日次実行の経路は安全。塞ぐなら検証を `build_short` 側か `Script` 側へ寄せる。

## 3. `figure` 有無の判定基準が2種類ある

採用ゲートは厳格な `_FIGURE_RE.search()`、カードの出し分け
（`compose_stage` / `ensure_grounded_card`）は緩い `figure.strip()` を見ている。

現状 `figure` は常に空なので到達しないが、**統計系統を戻したとき**に
`figure="2024年度"` のような非数量文字列で採用が quote 側で通り、カードは
数値カード側に落ちる。するとモデル生成値に一次資料の出典が付く（問題1と同型）。

統計系統を戻す前に、分岐にも `_FIGURE_RE` を使う（共有ヘルパ化）こと。

## 4. 画像の手動準備と「完全自動」が両立していない

`work/<id>/photo.jpg` の `id` は見出しのSHA1なので、**明日の見出しを知らないと
事前に用意できない**。NHKのRSSは数時間で入れ替わるため、前日に用意しても翌朝
同じ候補が残っている保証がない。

結果、無人実行の定常状態が「本日 0/2 本」になりうる。暫定策としては、題材に
依存しない汎用背景（官邸の国会議事堂写真など）へのフォールバックを1枚置けば
今日から回る。
