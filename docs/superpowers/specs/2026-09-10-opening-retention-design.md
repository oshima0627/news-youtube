# 冒頭の維持率を上げる — 設計

2026-09-10。**まだ実装しない。** 9/12 のライブ測定（`HANDOFF.md` Task 1）の結果を
見てから着手を判断する。ライブが通ればショートの優先度は下がる。

## 何を疑っているか

**冒頭で落ちなければ伸びる。** 根拠:

- 30日窓 n=51 で r(平均視聴率, 再生数) = **0.65**。上位半分の再生中央値 1,776 /
  下位半分 1,263（[`docs/analytics-2026-09-10.md`](../../analytics-2026-09-10.md)）
- 前回調査では **3秒地点（5%）の残存率だけでも相関は r=0.67** で、維持率全体と同じ
  だった。落ちる場所は全部が冒頭で、50%地点以降の傾きは勝ち負けでほとんど変わらない
  （[`docs/analytics-2026-09-07.md`](../../analytics-2026-09-07.md) 3節）
- 平均視聴率の中央値は **2025年10月 95.3% → 2026年8月 69.0%**。再生数の差4.1倍は
  当時の需要（高市政権発足）と交絡するが、**維持率の差は題材の需要では説明が付かない**

**26ポイントぶんの余地がある。** ただしこれは「本数 × 約1,300」の枠内での
約1.4倍であって、桁を変える力は無い（CLAUDE.md「チャンネルの現在地」）。

## いまの画面（実装を読んで確認した）

`build_short.compose_base` が作る土台1枚が **59秒間ずっと同じ**で、
`compose_over` がテロップ帯だけを差し替える（1本あたり20枚前後）。

```
y=0     HEADLINE_H=340   見出し（render_headline・最大2行）
y=340   PHOTO_H=740      発言者の実写
y=1080  TELOP_H=280      テロップ（ここだけ切り替わる）
y=1360  CARD_H=341       根拠カード（render_quote / render_figure）
```

**つまり冒頭3秒に固有の絵は存在しない。** 視聴者が最初に見るのは、
見出し＋実写＋根拠カードが全部載った完成形である。

## 変更（1点だけ）

`write_frames(workdir, base, frames)` が全フレームに同じ `base` を使っている。
ここに **冒頭用の土台をもう1枚**渡し、先頭 `OPENING_SECONDS` ぶんのフレームだけ
そちらを使う。

- 冒頭用の土台は、**引用の中の1つの数字（または最も短い一文）を画面いっぱいに1つだけ**置く。
  見出し・実写・出典キャプションは出さない
- **文字列は逐語引用の連続した部分文字列に限る。** `ground_excerpt` を通す。
  言い換え・省略記号の挿入はしない（CLAUDE.md の禁止事項）
- **関門は増やさない。** 冒頭用の土台も `compose_base` と同じく `quote` を
  キーワード必須引数で受ける。渡し忘れた経路は描画そのものができない
- `figure` 系統（数値カードを使う題材）では `figure_value` を使う。
  発言系統では引用から取る。判定は既存の `evidence.has_figure` を使い、
  **新しい判定基準を作らない**（CLAUDE.md「判定基準を2箇所に書かない」）

`OPENING_SECONDS` の初期値は **2.5秒**。理由: テロップ1枚の平均が約3秒
（59秒 ÷ 20枚）なので、フレーム境界を割らずに1〜2枚ぶんを置き換えられる。

## どう測るか

**判定は書き出した動画の感想ではなく、YouTube Analytics の実測で行う。**

- **指標**: `audienceWatchRatio` の **20%地点（12秒）の残存率**。
  平均視聴率ではなくこれを使うのは、前回 r=0.67 が出ている指標で、
  かつ「冒頭で落ちたか」を直接見ているため
- **配置**: A（現行）と B（冒頭カードあり）を **日替わりで交互**に出す。
  題材の当たり外れとニュースサイクルの流れを両群に均等に配る。
  1日2本なら同じ日は同じ群にする（朝夕で分けない — 枠ごとの差と混ざる）
- **本数**: 各 **15本**（1日2本なら15日）
- **評価の時点**: 公開から3日後。前回調査で「初3日の再生 ÷ 累計 の中央値は99%」
- **判定**: 12秒残存率の中央値の差が **10ポイント以上**あるときだけ採用する。
  それ未満は「差が無かった」として **B を捨てる**

### 交絡として先に潰しておくもの

- **BGM。** 次の `run_daily.py` から全動画に自作曲が入る（CLAUDE.md「BGM」節）。
  **A も B も BGM 導入後の動画だけで取る。** またぐと音の変更と冒頭の変更を
  分離できない
- **選挙シリーズ。** 沖縄県知事選が終わると題材の傾向が変わる。
  実測では選挙8本 1,433 / 73.7% とそれ以外43本 1,316 / 70.5% で差は無かったが、
  **群ごとの選挙本数が偏っていないか**は集計時に数える
- **`R_dirwcTjqs` 型の配信されない動画。** 43本中2本（約5%）で起きる。
  **12秒残存率の集計から再生100未満の動画を外す**（分母が小さすぎて中央値を歪める）

## やらないこと

- **見出し・引用・出典の文字列をモデルに書き直させない。** 変えるのは
  **どの順で見せるか**だけ
- **`compose_base` の `quote` キーワード必須引数を緩めない**
- **A/B の判定に「再生数」を使わない。** 再生数は本数と需要で動く。
  変更が効いたかを見るなら維持率
- **n=5 で結論を出さない**（CLAUDE.md「実例1件で門番の語彙を増やさない」と同じ理由）。
  15本ずつ揃うまで判定しない
- **効果が出なかったときに `OPENING_SECONDS` を動かして測り直さない。**
  それは「差が出るまで条件を変える」ことになる。捨てる

## これが外れる形

- 12秒残存率が **B のほうが低い** → 冒頭で完成形を見せないと離脱する、が正しい。
  すぐ戻す
- **どちらも 2025年10月の95.3%に届かない** → 原因は冒頭の構図ではなく別のところ
  （題材・声・尺・テロップの速度）にある。**その場合はこの設計ごと捨てて、
  旧フォーマットの動画を実際に見るところからやり直す**
