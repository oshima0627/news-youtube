# 長尺（16:9・約4分）パイプラインの設計

2026-08-20。オーナーの依頼「長尺とショート動画を作れるだけ作成してください」に対し、
**長尺の制作機能がリポジトリに存在しなかった**ため新規に設計した。

## 何を作るか

**1本に3題材を束ねたまとめ形式。** 各題材はそれぞれ独立した一次資料（国会会議録の
逐語引用）を持ち、章（チャプター）で区切る。約4分。1920x1080。

**1日1本、JST 18:00 に予約公開する**（オーナー決定 2026-08-20）。
ショートの枠（07:30 / 18:30）とは別枠。

### なぜまとめ形式か

「1題材を深掘り」は、同じ論点について複数の会議・発言者から引用を集める
**新しい取得ロジック**が要る。関連性の確かめ方も新しく考えることになるが、
既存の採用ゲートは関連性を判定していない（CLAUDE.md 未解決項目）ので、
判定できないものをもう1つ増やすことになる。

まとめ形式なら、**1題材＝現在ショートで作っているものと同じ単位**なので、
`collect_news` → `evidence.collect()` → `commons.resolve()` の経路をそのまま
1題材ずつ通せる。新規に作るのは「束ねて描く」部分だけになる。

## 構成

```
run_long.py（新規）
  ├─ 人が選んだ3件を --only <id> <id> <id> で受ける
  └─ 題材ごとに
       ├─ evidence.collect()      ★採用ゲート（ショートと同一）
       ├─ commons.resolve()       発言者の顔写真
       ├─ script_writer.write_segment()   1題材 約430字（約75秒）
       └─ narrate.synthesize()    パートごとに別々の wav
  ├─ build_long.build()           1920x1080 に組み、ffmpeg で連結
  └─ upload_youtube.py            ← 無改造で再利用
```

新規ファイルは3つ:

| ファイル | 役割 | 依存 |
| --- | --- | --- |
| `scripts/cards_wide.py` | 16:9 の各要素を描く | `draw.py` の原始関数のみ |
| `scripts/build_long.py` | パートを並べて mp4 にする | `cards_wide` / `narrate` / `telop` / `evidence` |
| `scripts/run_long.py` | 題材選定から予約公開まで | 既存の各モジュール |

**既存の `cards.py` / `build_short.py` は変更しない。** ショートは収益化の本線で、
動いているものを揺らす理由が無い。共通化は `draw.py`（フォント選択・折返し・
数字正規化）の層で足りている。

`slots.py` と `narrate.py` と `script_writer.py` だけは既存に手を入れる（後述）。

## 画面（1920x1080）

縦型の積み上げをそのまま横に伸ばすと写真が間延びするので、左右に分ける。

```
┌─────────────────────────────────────────┐
│ ① 見出し（章番号つき）                    │ 見出し帯 h=180
├──────────────────┬──────────────────────┤
│                  │                      │
│   実写 840x660   │   引用カード 900x660  │  y=210..870
│                  │   （逐語引用＋出典）  │
├──────────────────┴──────────────────────┤
│ テロップ（ナレーション同期）              │ h=180
└─────────────────────────────────────────┘
```

導入と結びは、写真・引用カードの代わりに**3題材の見出しを並べた目次面**を出す。

## 関門は増やさない。同じものを通す

CLAUDE.md「関門は1つにして、全経路がそれを通る形にする」に従い、**新しい検証を
作らない**。既存の関門をそのまま通す:

- `evidence.collect()` — 題材ごと。逐語引用が取れなければその題材は使わない
- `evidence.ground_excerpt()` — `cards_wide.render_quote` を呼ぶ
  `build_long.compose_segment()` で通す。`quote`（逐語引用）は
  **キーワード必須引数**にする。渡し忘れた経路は描画そのものができない
- `state/used.json` — 3題材ぶんの出典URLと検索語を記録する。翌日のショートが
  同じ発言を使うことはない
- `state/published.json` — 長尺も1本として記録し、枠の二重予約を防ぐ

## 導入と結びに事実を書かせない

導入・結びの2パートだけは特定の一次資料に紐づかない。ここに数値や評価を書くと、
**検証されない主張が画面と音声に乗る**（画面の根拠カードは逐語引用で検証されるが
ナレーションは検証されない、という既存の穴が長尺では2パートぶん広がる）。

対処は生成の指定側に置く: 導入・結びは**各題材の見出しの読み上げと定型句だけ**とし、
数値・評価・見通しを書かないことをプロンプトで明示する。文字数も短く抑える
（導入 60〜80字、結び 40〜60字）。

## 既存への変更（3箇所）

### `slots.py` — 長尺の枠を足す

```python
SHORT_SLOTS = (time(7, 30), time(18, 30))
LONG_SLOTS  = (time(18, 0),)
def pending_slots(now, days_ahead=0, kind="short") -> list[datetime]
```

`PUBLISH_SLOTS` は `SHORT_SLOTS` の別名として残す（既存の呼び出しと
テストを壊さないため）。

### `narrate.py` — 尺の窓を引数にする

`synthesize()` は 56〜61秒の窓（`TARGET_MIN`/`TARGET_MAX`）に固定されている。
長尺のパートは 75秒前後・導入は 12秒前後なので、この窓では毎回警告が出る。

窓を**省略可能な引数**にし、既定値は現在の定数のままにする。ショート側の
呼び出しは1文字も変えずに現在の挙動を保つ。

### `script_writer.py` — 題材1件ぶんの台本を書く関数を足す

`write()`（60秒ショート用、330〜355字）はそのまま。長尺のパート用に
`write_segment()` を足す。返す型は `SegmentScript`:

| 項目 | 中身 |
| --- | --- |
| `headline` | 章の見出し（20文字以内） |
| `narration` | 約430字（75秒相当。0.171秒/字） |
| `subtitle` | テロップが作れなかったときの静止字幕（40文字以内） |
| `quote_excerpt` | 逐語引用からそのまま抜き出した一節（25文字以内） |

`title` / `tags` は動画1本に1つなので、パートではなく `write_long_meta()` で
3題材の見出しから別に作る。

## 章（チャプター）

パートごとの実尺が分かるので、`description` の先頭に YouTube の章として
書き出す。長尺だけの機能で、実装コストはほぼ無い。

```
00:00 きょうの3つの論点
00:14 ① 超党派議員団が訪中へ
01:29 ② 声も権利保護の対象に
...
```

YouTube の章は「00:00 から始まる」「3つ以上」「各章10秒以上」が条件で、
5パート構成（導入＋3題材＋結び）はこれを満たす。

## 尺の検証

ショートは 56〜61秒の窓を外れたら警告を出す（`build_short.verify_duration`）。
長尺に固定の窓は無いので、代わりに**音声の合計と mp4 の実尺が ±2秒以内に
収まっているか**を見る。ずれていれば無音や取りこぼしが出ているので警告する。

## テスト（実装前に書く）

| 対象 | 確かめること |
| --- | --- |
| `cards_wide` | 1920x1080 で返る。見出し・引用・出典が枠内に収まる |
| `build_long` | モデルが捏造した `quote_excerpt` が機械抽出に差し替わる |
| `build_long` | パートを跨いだテロップの時刻が、パートの開始位置ぶんずれる |
| `build_long` | 章タイムスタンプの書式（`00:00` / `01:29`） |
| `slots` | 長尺枠 18:00 が `kind="long"` でだけ返る。既存の挙動は変わらない |
| `script_writer` | パートの字数指定と、0.171秒/字から出る秒数が対応している |

## 引き受けるリスク

**長尺は「AI音声＋静止画」形式が量産型ポリシー（2025-07-15 改定）に
当たると見られる危険が、ショートより高い。** 尺が長いぶん「解説としての
付加価値」を問われやすい。

**緩和は既存と同じ「全題材が逐語引用の一次資料を持つ」という一点だけで、
新しい防御は増やしていない。** これを承知のうえで進める（オーナー判断
2026-08-20）。

判断材料として、この形式の1本目を出した後に、
- 表示回数と平均視聴時間（`yt-analytics.readonly` は取得済み）
- チャンネルに対する収益化審査の状態

を見てから2本目以降の頻度を決めるのが安全。パイプラインは1日1本を作れるが、
**毎日出すことを前提にしない。**
