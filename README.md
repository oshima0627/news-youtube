# news-youtube

チャンネル「[日本の最新ニュースまるわかり](https://www.youtube.com/@%E6%97%A5%E6%9C%AC%E3%81%AE%E6%9C%80%E6%96%B0%E3%83%8B%E3%83%A5%E3%83%BC%E3%82%B9%E3%81%BE%E3%82%8B%E3%82%8F%E3%81%8B%E3%82%8A)」
（`UCYHTfHJOoETzvpx-VZlUTng`）のショート動画を制作して投稿するパイプライン。

設計は [`docs/superpowers/specs/2026-08-10-news-youtube-design.md`](docs/superpowers/specs/2026-08-10-news-youtube-design.md)。

## 前提

**登録者2,845人で収益化要件の登録者数はクリア済み。止まっていることだけが失格要因。**
最終投稿は 2025-12-11 で、約8か月停止している。

ただし 2025-07-15 の改定で「量産型のコンテンツ」は収益化不可と明記された。
既存48本の「AI台本 → 読み上げ → 画像を貼る」形式はこの記述に該当しうるため、
**同じ形での再開はしない。**

**止まったことに気づく仕組みも持っている。** `.github/workflows/watchdog.yml`
が毎日、チャンネルの公開RSSを外から見て、直近7日に1本も公開されていなければ
GitHub からオーナーにメールが届く。ログや実行環境の状態ではなく
**YouTube側の実際の公開状況**だけを見るので、原因（PCが落ちた・タスクが
未登録・ネットワーク不通など）が何であっても「止まっていること」そのものを
取りこぼさずに捕まえられる。詳細は [`docs/daily-workflow.md`](docs/daily-workflow.md)
の「止まったら知らせる」を参照。

## 設計方針：一次資料先行型

RSSで題材を拾ったら、公開前に必ず一次資料を引きに行き、
**根拠となる数値か逐語引用が取れた題材だけを採用する。**
取れなければ捨てて次の候補へ進む。

現状は国会会議録API（発言の逐語引用）のみ。e-Stat と官庁報道発表は後から足す系統で、
`collect()` は系統を並べるだけの形にしてあるため追加は容易。e-Stat は一旦見送っており、
理由は `scripts/evidence.py` の `collect()` のコメントを参照（統計表のメタデータを実際の
統計値と誤って採用ゲートを通してしまうため、`getStatsData` で実値を取れるようになってから戻す）。

「一次資料が取れなければ公開しない」を採用条件そのものにすることで、
量産型ポリシーと完全自動での事実誤認リスクを、同じ1つの関門で塞いでいる。

## 画像

**発言者の顔写真を自動で取る。** 事前準備は要らない。

発言者名から **ja.wikipedia のその人物の記事画像**を引き、Commons で
ライセンス（CC BY / CC BY-SA / CC0 / PD のみ）と大きさを確かめて使う。
人物名の全文検索は使っていない — 集合写真や別人が混ざったとき、誰が写って
いるかを機械的に確かめる手段が無いため。記事と人物は1対1なので、記事の
代表画像なら写っている人物が確定する。

発言者の画像が無いとき（政府参考人など。実測11人中3人）は**国会議事堂**の
写真に落ちる。両方だめなときだけ、その題材を見送る。

自動で選ばれた1枚を差し替えたいときだけ手を出す:

```bash
python scripts/fetch_photo.py work/<id> --speaker 片山さつき   # 別の人物で探す
python scripts/fetch_photo.py work/<id> <画像URL>              # URLを直接指定
```

`photo.jpg` と `license.json` が既にあれば自動取得は行わないので、置いた
画像はそのまま使われる。

## パイプライン

動画は2種類ある。**ショート**（縦1080x1920・約60秒・1題材）は `run_daily.py`、
**長尺**（横1920x1080・約4分・3題材を章で束ねる）は `run_long.py` で作る。
枠はショートが 07:30 / 18:30、長尺が 18:00 で分けてある（`slots.py`）。

`run_daily.py` を1回起動するだけで、その時点の残り枠の数だけ作り、
YouTube側の予約公開に載せて終了する。PC が日中落ちていても定刻に公開される。

```
run_daily.py
  ├─ collect_news.py            RSS巡回 → 候補20件（別プロセス。全滅なら中止）
  │                             国会で議論されえない題材はここで落とす
  └─ 候補を上から順に、枠が埋まるまで
       ├─ 当日すでに使った出来事・発言なら見送り
       ├─ evidence.collect()    ★採用ゲート（根拠＋出典URLが無ければ見送り）
       ├─ commons.resolve()     発言者の顔写真を自動取得（上記「画像」）
       ├─ script_writer.write() 一次資料だけを渡して台本生成
       ├─ narrate.synthesize()  VOICEVOXで音声合成
       ├─ build_short.build()   根拠カード + テロップ + 音声 → 1080x1920
       └─ upload_youtube.py     private → --schedule で 07:30 / 18:30 予約
```

`run_daily.py` が別プロセス（`subprocess`）で起動するのは
`collect_news.py` と `upload_youtube.py` の2つだけで、採用ゲートと台本生成は
`evidence.collect()` / `script_writer.write()` を**直接 import** して呼ぶ
（環境不備と題材固有の失敗を例外の型で見分けるため）。
`verify_source.py` / `write_script.py` / `fetch_photo.py` は同じ処理を
手で1件ずつ確認するための単体CLIとして残してある。

長尺は同じ部品を使いつつ、題材を**人が選ぶ**ところだけが違う:

```
run_long.py --only <ID> --only <ID> --only <ID>
  └─ 題材ごとに evidence.collect() → commons.resolve() → script_writer.write_segment()
  ├─ 導入・結びは定型文（モデルに書かせない。一次資料に紐づかないパートなので）
  ├─ narrate.synthesize()  パートごとに合成（尺の窓は呼び出し側が渡す）
  ├─ build_long.build()    1920x1080 に組み、音声を連結して1本にする
  └─ upload_youtube.py     private → --schedule で 18:00 予約
```

設計と、引き受けたリスク（長尺は量産型ポリシーに当たる危険がショートより高い）は
[`docs/superpowers/specs/2026-08-20-long-form-design.md`](docs/superpowers/specs/2026-08-20-long-form-design.md)。

公開後に問題が判明したら `scripts/unpublish.py <video_id>` で即座に戻す。

## 根拠カード

画面中央のカードには必ず一次資料の出典（会議名・日付・発言者）が印字される。
したがってカードに出す文字列は一次資料に由来していなければならない。

| 一次資料 | 画面に出るもの |
| --- | --- |
| 発言（`Evidence.figure` が空。現状はこれだけ） | 逐語引用そのものを引用カードに出す |
| 数値（統計・公表。系統復活後） | その数値を数値カードに出す |

発言系では、台本モデルが返した `quote_excerpt` が逐語引用の**部分文字列**である
ことを実際に確認し、外れていたらモデルの出力を捨てて逐語引用の先頭から機械的に
抜き出した文字列へ差し替える（`evidence.ground_excerpt`）。
これがないと「モデルが作った文字列に一次資料の出典が付く」ことになる。

**この関門はカードを描く直前（`build_short.compose_base`）に置いてある。**
`run_daily.py` にだけ置いていたときは、`write_script.py` → `build_short.py` を
手で叩く経路が検証を通らなかった。逐語引用は `compose_base` のキーワード必須
引数なので、渡し忘れた経路は描画そのものができない。

どちらのカードを使うかも同じ基準（`evidence.has_figure`）で決める。採用ゲートが
「数量を含む文字列か」で判定しているのに出し分けが「空でないか」だと、
`figure="2024年度"` のような文字列でモデル生成値に出典が付く。

## 画像素材

取得元を以下に限定する。**ホワイトリスト外からは取得しない。**

| 出所 | ライセンス | 条件 |
| --- | --- | --- |
| 首相官邸 | PDL1.0 | 出典明示＋加工した旨と加工主体の記載 |
| 各府省 | 政府標準利用規約2.0 | 出典明示 |
| Wikimedia Commons | CC BY / CC BY-SA / PD | クレジット必須 |

いずれも元からウォーターマークがないため、除去処理は存在しない。
報道機関の写真は使わない。

## 状態

**稼働中。ただし自動では走らない。** 2026-08-18 にタスクスケジューラの
定例実行（`news-youtube` / 06:00）を削除し、**セッションで人が起動する運用**に
切り替えた。画像は発言者から自動で取るので事前準備は要らない。

**なぜ自動をやめたか。** 素の `run_daily.py` は候補の先頭から採るので、
見出しと引用が噛み合わない動画をそのまま予約してしまう。予約公開まで
到達した実例が2件ある（2026-08-13 の番組宣伝、2026-08-17 の福岡県条例＋
憲法審査会答弁）。どちらも人が気づいて戻すまで止まらなかった。
採用ゲートは関連性を判定していない（CLAUDE.md「未解決」）ので、
**題材を選ぶ人がいる前提でしか回せない。**

起動のしかたは [`docs/daily-workflow.md`](docs/daily-workflow.md) の
「セッションで1本作る」。人が候補の中身を見て `--only` で選ぶ。

**代償として、起動しない日は0本になる。** 収益化要件は90日で3本以上で、
気づく仕組みは `.github/workflows/watchdog.yml`（直近7日に1本も公開されて
いなければGitHubからメール）だけになった。**この監視を止めないこと。**

同日、`docs/known-issues.md` の未検証項目をすべて確認して閉じた。
未解決として残っているのは**番組宣伝の見出しが題材として残る件だけ**で、
これは門番の語彙を決めるだけの実例がまだ無いので保留にしてある。

枠が埋まっている日は何も作らずに終わる（`run_daily.taken_slots`）。
先の日付ぶんを `--days-ahead` で作り置きしても、あとから同じ枠に
2本目を載せることはない。

運用手順（初回認証・環境変数・ログの読み方・事故ったときの戻し方・
タスクスケジューラ登録コマンド）は [`docs/daily-workflow.md`](docs/daily-workflow.md) を参照。

## 素で走った定例実行は、見出しと無関係な動画を予約することがある

**2026-08-17 に2例目が起きた**（1例目は 2026-08-13 の番組宣伝、`docs/known-issues.md`
5番）。定例実行が「福岡 県が議員などの不当な要求から職員を守る条例案提出方針」の
見出しに、憲法審査会の臨時国会召集・同性婚違憲判決の答弁を付けて予約した
（`zC8OJmUT9Us`）。公開前に気づいて `unpublish.py` で戻し、同じ枠を人が選んだ
題材で埋め直した。経緯は `docs/known-issues.md` 5-b番。

**この形の失敗はゲートでは止まらない**（CLAUDE.md
「未解決：採用ゲートは関連性を判定していない」）。**予約された動画は、
公開時刻より前に見出しと引用が噛み合っているかを人が見ること。**
差し替えるなら [`docs/daily-workflow.md`](docs/daily-workflow.md) の
`--only`（人が題材を選ぶ経路）を使う。

**差し替え先は、母数を広げないと見つからないことがある。** 8/17 は上位20件では
採用可6件のうち噛み合っていたのが1件だけ（しかも同日すでに使った題材）で、
一度は「差し替えられる題材が無い」と判断した。`collect_news.py --limit 45` で
門番を通った45件すべてを見ると採用可は12件あり、噛み合う題材が21位以下に
**4件**残っていた（拉致問題の中学生サミット、原爆の日の式典、安保3文書の
有識者会議、介護保険証とマイナ）。`run_daily.py --candidates 45` で
そのまま同じ経路に通せる。
