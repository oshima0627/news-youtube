# 評価ルーブリック：見出しと一次資料の関連性

採用ゲート（`evidence.collect`）を通った題材を、**独立した評価者**が採点するための基準。
生成側（ゲート・台本モデル）はこのファイルを読まない。

## なぜ必要か

採用ゲートが判定しているのは「**検索語が同じ文脈に2語以上固まって現れるか**」（`evidence.find_passage`）。
これは一次資料の**実在**と**話題の近さ**は保証するが、
「その発言が見出しの報じた出来事を裏付けているか」は判定していない。
`docs/known-issues.md` 5番（番組宣伝）は、この凹みが表に出た1例にすぎない。

## 採点基準

見出しが報じている**出来事**を、逐語引用が裏付けているかを 1 / 3 / 5 で採点する。
2 と 4 は評価者が補間してよい。

| 点 | 状態 | 目印 |
| --- | --- | --- |
| **5** | 引用が見出しの出来事そのものを直接扱っている | 引用中の主題・数値・論点が見出しと一致する |
| **3** | 同じ政策テーマだが、引用が扱っているのは**別の論点**または**別の時点** | テーマ語は共通するが、見出しの出来事は引用に現れない |
| **1** | 報じられた出来事が存在しない／引用が別の話題 | 番組宣伝・特集告知の見出し。検索語が偶然一致しただけ |

### 判定の手順

1. 見出しから「**報じられた出来事**」を1文で書き出す（例:「政府が消費税減税の基本方針を決定した」）
2. その出来事が逐語引用の中に現れるかを確認する
3. 現れない場合、テーマだけが共通なのか（3）、無関係なのか（1）を分ける
4. **必ず判定理由を残す**。理由の無いスコアは再現できない

### 追加でチェックする2項目（二値）

| 項目 | 不合格の条件 |
| --- | --- |
| **時点整合** | 見出しの出来事と引用の時点が1年以上ずれている |
| **カード先頭** | `ground_excerpt` が引用の**先頭**から抜き出すため、先頭部分が見出しと無関係だと画面に無関係な文が出る |

## 合格ライン

- **1点が1件でもあれば不合格**（クリティカル項目。スコアの高さで買い戻せない）
- 3点以下が全体の 1/3 を超えたら、ゲートの設計を見直す

**理由**: 1点は「報じられた出来事が無い」＝解説として成立しない。
これは平均点で薄めてよい種類の失敗ではない。

## 重み付けの意図

技術的な合否（一次資料が実在するか・引用が逐語か）は既存のゲートとテストが担保しており、
**そちらは満点が出て当たり前**。差がつくのは関連性だけなので、この1軸に絞って採点する。

## 使い方

`recipes/*.json` の `headline` と `evidence.quote` だけを評価者に渡す。
台本（`script.json`）や公開タイトルは渡さない。

**理由**: 公開タイトルは引用に寄せて作られているため、
それを見てから採点すると「タイトルと引用は合っている」という別の判定になり、
見出しと引用のズレが見えなくなる。
